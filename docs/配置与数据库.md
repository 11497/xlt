# 配置与数据库说明

## 环境变量

复制 `.env.example` 为根目录 `.env`，导入任意 `config` 模块时由 `config/__init__.py` 统一加载。系统环境变量优先于 `.env`。除 `config/` 内部外，业务代码不得直接读取环境变量、密钥、服务地址或运行参数。

| 变量                    | 说明                                     |
|-------------------------|------------------------------------------|
| `DB_HOST`               | MySQL 主机地址                           |
| `DB_PORT`               | MySQL 端口，默认 `3306`                  |
| `DB_USER`               | MySQL 用户名                             |
| `DB_PASSWORD`           | MySQL 密码                               |
| `DB_NAME`               | 数据库名；使用 `sql/db.sql` 时应为 `xlt` |
| `JWT_SECRET_KEY`        | 足够长的随机 JWT 签名密钥                |
| `ES_HOST`               | Elasticsearch 主机地址                   |
| `ES_PORT`               | Elasticsearch 端口，默认 `9200`          |
| `CHAT_API_KEY`          | 聊天回答服务 API Key                     |
| `UTILITY_API_KEY`       | 问题重写、恶意检查和标题总结服务 API Key |
| `EMBEDDING_API_KEY`     | 向量化服务 API Key                       |
| `RERANK_API_KEY`        | 精排服务 API Key                         |
| `OSS_ACCESS_KEY_ID`     | OSS AccessKey ID                         |
| `OSS_ACCESS_KEY_SECRET` | OSS AccessKey Secret                     |

`.env` 已被 Git 忽略，不得提交真实凭证。`.env` 中的 OSS 项只有 AccessKey；`bucket_name` 和 Endpoint 写在 `config/oss_config.py`。模型名称、召回参数和文件限制位于 `config/` 下对应模块；Worker 与对账运行参数位于 `config/worker_config.py`，也可在 `.env.example` 中以注释查看。

## AI 配置

聊天、辅助任务、向量化和精排服务地址分别由 `config/ai_config.py` 中的 `CHAT_BASE_URL`、`UTILITY_BASE_URL`、`EMBEDDING_BASE_URL` 和 `RERANK_BASE_URL` 配置。当前对话和辅助任务模型为 `deepseek-ai/DeepSeek-V3.2`，向量模型为 `Qwen/Qwen3-Embedding-8B`，精排模型为 `Qwen/Qwen3-Reranker-8B`；模型名称和生成参数应在该文件中修改。

提示词正文位于 `config/prompts/`，包括：

- `system.md`：知识库问答
- `summary.md`：会话标题总结
- `malicious_check.md`：内容安全检查
- `rewrite.md`：结合历史对话重写问题

编辑模板时必须保留运行时占位符，例如 `{conversation}`、`{user_input}`、`{conversation_history}` 和 `{user_question}`。Elasticsearch 创建知识库索引使用 `ik_max_word` tokenizer，必须安装 IK 插件。

## 数据库初始化

空环境首次初始化：

```text
SOURCE sql/db.sql;
```

`sql/db.sql` 不是幂等迁移脚本，不能在已完成初始化的数据库上重复执行。项目当前不提供增量 SQL。全新环境直接执行 `SOURCE sql/db.sql` 即可。已有数据库需先备份，再完全重置 MySQL、ChromaDB、Elasticsearch 和 OSS 后重新初始化。

当前 `sql/db.sql` 已包含逻辑删除字段（业务表 `is_deleted`/`deleted_at`）、`document` 表的状态字段（`status`/`error_message`/`retry_count`/`chunk_count`）、`document_task` 的 Worker 租约字段和异步任务表。

业务删除语义（逻辑删除、墓碑改名、索引真实删除、OSS 保留）见[架构与功能说明](架构与功能.md)。`document_task` 只做任务状态流转，不参与业务软删除。用户名 4–15、角色名/知识库名 1–15 的业务长度限制不变；墓碑名 `{原名}__{uuid32}` 会超过该上限，因此不会与合法新建名称冲突。

文档异步索引依赖独立 Worker；对账服务用于恢复卡死任务和补齐索引，属于可选的运维进程：

```text
uv run python -m ai.indexing_worker        # 消费索引/删除任务
uv run python -m ai.reconciliation_service # 定期对账（可选）
```

后端和 Worker 需同时运行，否则上传的文档会停留在 `pending` 状态；未运行对账服务时，任务仍可由 Worker 正常处理，但卡死任务和索引不一致不会被定期修复。

Worker 和对账服务支持以下可选环境变量（未设置时使用默认值）：

| 变量 | 默认值 | 说明 |
| --- | ---: | --- |
| `INDEX_WORKER_POLL_INTERVAL` | `2` 秒 | Worker 每轮任务处理后的轮询间隔 |
| `INDEX_WORKER_IDLE_SLEEP` | `3` 秒 | Worker 连续空转达到阈值后的休眠时长 |
| `RECONCILE_INTERVAL` | `600` 秒 | 对账服务轮询周期 |
| `RECONCILE_STUCK_TIMEOUT` | `15` 分钟 | 判定任务卡死的 processing 超时时间 |

索引或删除任务超过 `max_retries`（默认 `5`）后会停在 `failed`，对账服务不会自动重开 `delete` / `delete_kb`。Elasticsearch 或 Chroma 恢复后，可用下面的脚本把全部 failed 任务改回 `pending`（索引失败的文档会从 `failed` 改回 `pending`；删除中的文档保持 `deleting`），再由 Worker 幂等重试：

```text
uv run python scripts/reset_failed_document_tasks.py --dry-run
uv run python scripts/reset_failed_document_tasks.py
```

需要清空并重建本地开发数据库时才执行：

```text
SOURCE sql/reset-dev.sql;
SOURCE sql/db.sql;
```

`sql/reset-dev.sql` 会删除整个 `xlt` 数据库，只能用于可丢弃全部数据的本地开发环境。

## 常见问题

- **文档一直停在 `pending` 或 `deleting`**：没有启动 Worker。本地需同时运行后端和 `uv run python -m ai.indexing_worker`；Windows 的 `start.bat` 会启动 Worker。对账服务可选，不启动时正常任务仍能被 Worker 消费。
- **Elasticsearch 中文检索异常或创建知识库失败**：未安装 IK 插件。知识库索引使用 `ik_max_word` tokenizer。
- **任务停在 `failed`**：已超过 `max_retries`（默认 `5`）。排查 Elasticsearch / Chroma / OSS 后，用 `scripts/reset_failed_document_tasks.py --dry-run` 预览，再去掉 `--dry-run` 把任务改回 `pending`，由 Worker 幂等重试。
- **对账服务会不会删除 OSS**：不会。对账只恢复卡死任务、补齐未逻辑删除文档的索引，并报告疑似孤儿对象，不删除 OSS 文件。
- **Chroma 数据在哪**：默认写入项目根目录 `chroma_db/`，该目录已被 Git 忽略，重置本地环境时需一并清理。
