# 开发与部署说明

## 测试

```bash
uv sync --group dev
uv run pytest -q
```

测试覆盖会话和消息资源归属、管理员权限、聊天 NDJSON 事件顺序、生成失败或取消时的消息持久化、文本切片和密码校验。默认使用替身隔离 CRUD、检索和模型服务，不连接或修改 MySQL、Elasticsearch、OSS、ChromaDB 和模型 API。

## 文件与模型限制

- 支持 `.md`、`.txt`、`.pdf`、`.docx`
- 单文件不能为空，最大 10 MB
- 文件名长度 1–255 个字符，存储路径长度 1–500 个字符
- OSS 下载链接默认有效期 300 秒
- 文本切片最大长度 500，重叠长度 150
- 用户名 4–15 个字符，密码 6–20 个字符
- 角色名、知识库名 1–15 个字符
- 会话名 1–30 个字符，AI 自动标题目标为 2–20 个字符
- 公告标题 1–255 个字符，公告正文不能为空
- 聊天输入上限 2000 个字符，超限内容会被截断
- 实体 ID 和关联 ID 必须为正整数
- 角色-知识库权限为 `0`（只读）或 `1`（读写）

前端和后端都会校验文件扩展名、大小、空文件及文件名长度，具体实现以 `config/file_config.py` 和 `frontend/src/utils/uploadValidation.js` 为准。

## 部署注意事项

- 使用独立且足够强的 `JWT_SECRET_KEY`，不得提交 `.env`、数据库密码、API Key 或 OSS 凭证。
- 后端当前未配置 CORS；本地开发依赖 Vite 代理。前后端跨域部署时需配置可信来源的 CORS 或统一域名。
- 反向代理必须关闭 `/api/message/chat` 的响应缓冲和缓存。后端已返回 `X-Accel-Buffering: no` 和 `Cache-Control: no-cache`，使用 Nginx 时仍需检查代理配置。
- 文档上传依次写入 OSS、MySQL、ChromaDB 和 Elasticsearch；数据库写入失败时 OSS 对象保留用于人工核对，生产环境应补充对象留存策略和可观测性。
- 删除知识库或文档会异步真实删除 ChromaDB/Elasticsearch 索引，并将 MySQL 记录置为逻辑删除；OSS 对象保留用于留存。删除公告/附件和会话/消息仅修改 MySQL 逻辑删除标记。执行删除前应确认检索服务可用并做好数据库备份。
- 对账服务只恢复任务和补齐未逻辑删除文档的索引，不删除 OSS 对象。
- 用户密码使用 Argon2id 哈希保存；已有明文密码必须先迁移或重置。
